<a11y-collapse heading-button="heading-button"><h2 slot="heading">Higher order schema</h2><div slot="content"><ul><li><code>title</code> — name of the work as a whole.</li><li><code>author</code> — who created this work.</li><li><code>description</code> — short description of the work to explain it.</li><li><code>license</code> — a valid license shorthand for the work as a whole.</li><li><code>metadata</code> — area for storing any additional details about the work. Core JSON Outline Schema intentionally keeps this open-ended; downstream systems (like HAXcms) define practical conventions in this area.</li><li><code>id</code> — a unique identifier for this work in the universe of all works.</li><li><code>items</code> — an array of schema elements which contain the pages / leaves of the structure of this outline.</li></ul></div></a11y-collapse><a11y-collapse heading-button="heading-button"><h2 slot="heading">Leaf / page element within the structure</h2><div slot="content"><ul><li><code>id</code> — the UUID / unique ID of the element.</li><li><code>indent</code> — how far to visually position the item inward. You could have something be the parent as a page but visually only be indented 2 levels.</li><li><code>location</code> — a file or resource that references the related data to display here.</li><li><code>slug</code> — a URI portion that is how this resource should be presented on the web. Can be the same as location but allows abstraction away from the actual location of the file via this attribute.</li><li><code>order</code> — a weighting as to the order relative to other items that match this parent level.</li><li><code>parent</code> — a UUID / unique ID of the element this is a child of.</li><li><code>title</code> — title of this item to display.</li><li><code>description</code> — short description of the item to explain it.</li><li><code>metadata</code> — a container for any additional details of information you need to ship.
